## 上下文状态规则（context-state）

长周期工作靠每条工作线的 `STATE.md` 恢复上下文，不靠重读全部文档。工作线列在下方索引中。

**新对话**：只读用户指定工作线的 `STATE.md`。其中有"运行中作业"时，先执行检查命令并更新 STATE。其他文件只按 STATE 的指针读：先 `rg -n` 定位，再读局部窗口（单次不超过约 200 行或 6000 字符），不整篇读报告、计划或日志。STATE 缺失、过期或与磁盘矛盾时，以磁盘上的结果为准并修正 STATE。

**记录**：`STATE.md` 覆盖写，不超过约 4000 字符，是给剩余工作的简报，格式见 `.agents/STATE_TEMPLATE.md`。`LEDGER.md` 只追加，每个事件一行：`时间 | 事件类型 | 内容与关键数值 | 路径或作业 ID`，只用 `rg` 检索。报告类文档面向人，STATE 只指向其标题。

**何时更新**（先追加 LEDGER，再重写 STATE；时间一律取自 `date` 命令，不估计）：提交、取消或发现失败的长作业后；得出结论后；做出或推翻决策后；用户给出新约束时（写原话）；对话结束或交接时；对话已很长时（更新后建议开新对话）。

**压缩规则**：只选与剩余工作相关的事实，不按时间复述；目标照录原文并写完成判据；已验证与未验证分开，已验证的带来源；失败的做法写进"死路"；下一步具体到命令；多文件来源全部列出，文件间矛盾写明双方出处与当前取舍；记录资料覆盖；长输出改写成能取回它的窄命令；重写时以旧 STATE、新 LEDGER 条目和磁盘结果为输入，不对旧 STATE 再摘要；超长时把稳定结论移入报告并留指针；写完更新索引里的"现状"。

**并行**：同一工作线同一时间只由一个对话重写 STATE。写前比对 `updated` 时间，较新则先合并。其他对话只追加 LEDGER。
